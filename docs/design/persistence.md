# Persistence Snapshot Format

## Цели
- Сохранение полного состояния [`Stub`](internal/service/service.go).
- Атомарная запись без частичных файлов.
- Расширяемость и человекочитаемость.

## Формат файла
Используется JSON-снапшот со структурой:

```json
{
  "version": 1,
  "updated_at": "RFC3339",
  "tuples": [
    {
      "k1": "...",
      "k2": "...",
      "k3": "...",
      "payload": "base64"
    }
  ]
}
```

Преимущества:
- соответствует структуре [`Tuple`](internal/service/service.go);
- автоматическое base64-кодирование бинарных payload;
- добавление новых полей через версионность.

## Протокол записи
1. Создать временный файл `*.tmp` в каталоге снапшота.
2. Записать JSON с `json.Encoder` (включая `SetIndent` для читаемости).
3. Вызвать `Sync()` у временного файла.
4. Закрыть файл и сделать `os.Rename(tmp, target)`.
5. Открыть каталог и выполнить `Sync()` для фиксации переименования.

Такой протокол обеспечивает атомарность (POSIX rename) и устойчивость к сбоям питания.

## Загрузка
- При старте `Stub` читает снапшот; отсутствие файла трактуется как пустое состояние.
- Неконсистентный JSON возвращает ошибку загрузки.
- Версионность позволяет вводить миграции при необходимости.

## Периодический сброс
- Интервал задаётся конфигурацией [`PersistenceConfig.Interval`](internal/config/config.go).
- Воркер вызывает [`Stub.SaveSnapshot`](internal/service/service.go) и логирует ошибки.
- При остановке сервера выполняется финальный `SaveSnapshot` с таймаутом.
