# План реализации фазы 2 (полная бизнес-логика KV-хранилища)

## 1. Цели и соблюдение спецификации
- Реализовать полноценное KV-хранилище с учётом ключевой структуры (`K1`, `K2`, `K3`).
- Гарантировать корректную обработку статусов `200`, `404`, `4xx/5xx` в соответствии с картой ошибок `statusError`.

## 2. Архитектура
- Источник данных — встроенное in-memory хранилище с возможностью замены на внешнее (PostgreSQL, Tarantool) через интерфейсы.

Возьми за основу mock реализацию из пакета scripts/swarm_stub/pkg/swarm, адаптируй ее под нужды задачи и внедри в сервисный слой. Сервисный слой должен работать в точности так же, как и mock просто через http интерфейс
